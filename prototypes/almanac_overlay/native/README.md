# Almanac ImGui development DLL — not yet Windows/runtime tested

Cross-subsystem entry point: [Almanac engineering status](../../../docs/almanac-engineering-status.md). PR #82 merged this preparation into Almanac; its final adapter source review passed, but this is not Windows/runtime or hook-install acceptance. The follow-on [Windows build and standalone diagnostic](WINDOWS_CHECK.md) now provides an isolated CMake target and F8 test-window source; it is not a game DLL and has not been Windows-built/run. This new work has not yet been independently reviewed.

`d3d11_panel.{h,cpp}` prepares the actual ImGui DX11 draw path, following Earthworks' real-swap-chain architecture without copying its monolithic interception/input code. It is outside normal plugin discovery, has no exports/DllMain and is not built by the host runner. It installs no IAT/Present/WndProc hook. No Windows compilation, GPU test, deployment or game execution has been performed. Independent review is outstanding. Do not drop this source into `plugins/` or enable it in a live game.

## Implemented source

- Explicit caller-supplied swap-chain initialization; no first-Present guessing, native globals or dummy swap chain.
- Owned ImGui context and COM references, initialization rollback on ordinary failure/C++ unwinding, context restoration, explicit same-owner shutdown.
- Earthworks-derived paper/ink styling and the synthetic read-only Almanac view.
- DX11 backend frames with dimensions from the back buffer and clamped elapsed time. No Win32 input backend, input capture, cursor changes, widgets or live Finance providers.
- Host-tested visibility policy auto-shows on the first allowed foreground frame. F8 then hides/reopens once per fresh press. Hiding retains resources; focus loss/minimization hides/disarms.
- Per-draw back-buffer/RTV references are released before return. All eight OM render targets and depth view are saved/restored in addition to upstream backend state handling.

## Explicit adapter candidate

A development entry point and DLL target exist in this isolated CMake project: see [DEV_PLUGIN.md](DEV_PLUGIN.md). Ordinary `build.bat` and plugin discovery remain unchanged; the explicit `build.bat almanac_overlay_dev` target invokes CMake and copies the DLL/config to `build/plugins`. That output must be the actual Tesmio runtime's plugin directory or be copied into a disposable runtime. No Windows build or deployment has occurred here. Config defaults permit the synthetic panel to auto-show when the DLL is loaded and its chain/window checks pass. The standalone diagnostic remains separate.

`graphics_adapter.{h,cpp}` implements callable creation-import/Present interception and physical F8 sampling. It is invoked by the isolated dev DLL's `TsmPluginStart()` only after matching-module checks and explicit development opt-in; it is not included in normal builds. It accepts no pre-existing HWND. After a successful original creation call it checks the matching engine return RVA `0x148C2`, a top-level current-process window with the executable's HINSTANCE and exact class `Workers & Resources: Soviet Republic`, and agreement with the returned swap chain's OutputWindow. It does not gate on the mutable title or assume visibility during creation. Unknown callers/windows are forwarded without selecting a chain.

Observation is independent of drawing permission. The development DLL sets permission from config, which now defaults true; there is no native modal-state provider, so this default may draw over native dialogs and is for disposable visual tests only. Focus, visibility and minimize checks still hide/disarm the panel. ImGui initializes only on the selected chain's Present callback, not during plugin Start or creation. Late installation still has no fallback. Windows compilation, hook review and runtime acceptance remain outstanding.

The installer rejects a creation IAT target that is already replaced, pins its containing DLL before publishing any detour, and uses expected-target compare/exchange rather than overwriting a competing slot change. It saves/forwards the prior Present function without Present1 substitution, suppresses nested overlay drawing, serializes drawing, rejects render-owner migration, and disables rendering after failures. Protection-restoration failure leaves any installed hook resident and disables drawing. It retains process-lifetime chain/panel references deliberately: this experiment has no unload or automatic replacement path. A shared Present vtable can affect other chains; those forward without drawing. This is source-level preparation, NOT verified coexistence or race safety.

The physical F8 high-bit sample feeds the hide/reopen toggle in the Present callback; it does not consume native input. Existing budget HUD F8 remains unchanged and may also react. The development DLL target is enabled in the isolated CMake project, but remains outside normal plugin discovery and is not copied into a game. The DLL is not Windows-built or deployed, and the panel is not visually verified in-game. Auto-show permits synthetic drawing without modal tracking—not interaction or live Finance access. Windows compilation, hook review and disposable-copy testing remain required.

## Development DLL wiring (not product-ready integration)

The development DLL calls the native adapter after validating the host and matching modules; the adapter observes game-chain creation, then initializes/draws on the selected chain's Present owner and forwards the original Present. Its source attempts to serialize drawing and rejects render-owner migration, but resize/device-teardown coordination and full hook coexistence remain unverified. F8 is sampled with the high/down bit (not the low transition bit). For production, development opt-in, focus/modal/native input safety and backend readiness must gate permission. This experimental DLL defaults synthetic permission on without modal tracking and is for disposable visual tests only. The existing `ui_overlay` HUD is a separate F8 consumer; both may react, so do not silently replace budget rendering. The DLL is unbuilt and untested in-game.

Do not call Draw for DXGI_PRESENT_TEST, foreign chains or an unverified owner. If callbacks pause, reset visibility/owner state before resuming. Draw failure means bypass overlay, not return fake Present success. A C++ exception/native fault is NOT proven recoverable by this code: disable further overlay entry according to a reviewed policy; do not blindly retry a possibly unfinished ImGui frame. Shutdown must be serialized on the render owner; do not rely on a global destructor during DLL unload.

Device removal/foreign chains are rejected; automatic replacement/recovery is not implemented. Shutdown/reinitialize must be explicit and must not race the hook. DPI policy is currently back-buffer pixels with default font/style: no claim of game-DPI correctness. OM/UAV, backend pipeline coverage, resize behavior, context affinity and Steam/other-overlay coexistence still need native review/acceptance. Backend state saving alone is not a complete GPU safety proof.
