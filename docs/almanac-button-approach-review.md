# Almanac button approach: independent review

The original [agent report](../export/almanac-evidence/almanac-button-approach-20261109/report.md) from `29056b2` is preserved unchanged. [Independent arithmetic](../export/almanac-evidence/button-approach-independent/arithmetic.txt) checks its row-stride, ordering and PE-mapping calculations against prior evidence. No game or plugin was run and no UI was changed.

## Corrections

- **No stride discrepancy:** `0x140374179–18a` divides a nonnegative byte span by **80**, not 96. Direct indexing at `0x1403741f6–201` also multiplies by `0x50`. The prior live report recorded begin/end/capacity differences of `0x280`/`0x2d0`: eight entries and capacity for nine at that instant, not unknown capacity. This is non-atomic and does not imply a safe insertion or current capacity.
- **Ordering:** for the normal loop before conditional skips, eight entries map `[0,1,7,2,3,4,5,6]`; nine map `[0,1,8,2,3,4,5,6,7]`. The newly appended entry is visited third, and original index **7**, not index 2, moves from position 2 to position 8. Index 2 remains at position 3. Skipped indices do not consume the normal loop's X advance; neither mapping proves visual position or execution.
- **Axis and input:** the loop's advancing `XMM6` is packed as the first position component with `XMM10` as the second at `0x14037423c–243`; prior evidence identifies it as horizontal for the examined geometry, not a verified vertical step. The operand at `[RBP+0x210]` is copied from the input object's `GetMouseSolid` output, not proven to be a constructed button rectangle. `Collision` receives a vector by value and the shared panel object; the interaction of panel fields, transformations, clipping and click latches remains unresolved. A generic snapshot of the mutable globals at an arbitrary time cannot establish which row item wrote them, that the handler ran, or real clipping.
- **Click gate:** `0x1403742fd JNZ 0x140374347` jumps to the state-writing block, not past it. The prior collision and input latch checks remain relevant; the report's 'skip state write' annotation is reversed.
- **Approach B is not proven purely additive or safe:** a separate button avoids appending to the native vector, but could still collide with native input, overwrite shared UI state or draw over native content. Manually setting native `game+0xc65c` to a synthetic index without a corresponding native entry may cause invalid access: e.g. host `0x14031d794–b1` forwards a nonnegative index to a vector accessor, and other consumers need examination. No authorization or recommendation to write these fields follows from this report. A plugin-owned selection state is a candidate to investigate, not an established safe solution. Native-content suppression remains relevant to either approach; merely drawing a separate button does not suppress the current page. Existing `FUN_14035F3E0` is a native helper with side effects, not a verified custom renderer; `FUN_14007C400` is not a demonstrated generic return API.
- **Coordinates and text:** the report replaces `XMM11` with the button-size constant in its proposed base formula without proving they are equal. Dynamic placement must account for actual context, skip rules and scale, not simply `count × pitch`. The repository rule requires newly minted private UI text IDs of at least 1,000,000, but a new ID is not necessarily required for every text rendering route (`INSTRUCTIONS.md`).

## Reported string evidence

The report includes `74 72 61 64 65 00 00 00` at VA `0x1408b21e4` and identifies it as `trade`. The stated section parameters map RVA `0x8b21e4` to file offset `0x8b11e4`; this arithmetic and ASCII decoding are consistent. The full VA is not an RVA (the report labels it both ways). The bytes, section mapping and EXE hash come from the same agent's report; without the EXE or an independently sourced authenticated extract, their provenance and the source file's hash cannot be independently verified here. Matching the string supports the static branch analysis, not runtime execution.

## Decision status

A separate button remains a **design candidate** because it avoids the known append reorder; it is not yet established as safer overall. Compare it against native insertion for actual dynamic positioning, input ownership, clipping, side effects, content replacement, and native return. The preferred product remains a separate global Almanac section, with an Economy & Trade page as fallback if the section is unsafe. A context-specific test must eventually verify same-row fit and clickability alongside all eight tiles, at relevant resolutions/scales, as well as native return; such a test requires separate authorization for any instrumentation, deployment or process modifications. Read-only snapshots alone do not test a new button.

## Design comparison `0ff2b03`

The agent's [comparison](../export/almanac-evidence/almanac-design-comparison-20261109/report.md) is preserved unchanged. It usefully proposes mod-owned open/close state and avoids writing a made-up native selected index or directly replacing the panel pointer. Neither separation nor a second `Collision` call automatically prevents double input, interfering with the game, or a vanilla page drawing under the Almanac. The report itself describes that overlap while its summary says native suppression is unnecessary; replacement/suppression is still an open requirement. Keeping the Almanac open until re-clicked is not an adequate default for leaving the sidebar without a deliberate product decision.

The comparison repeats previously corrected errors: the observed capacity was nine at capture, not unknown; the mapping moves native index 7 from third to ninth position (before skips), not from seventh to eighth; and the XMM6 advance was labeled vertical despite its use as the first position component. Its proposed base expression substitutes `0x14090aaa0` for `XMM11` without evidence. The suggested raw-global snapshot cannot establish the fit or clickability of an unbuilt button; the latter needs a separately authorized context-specific integration test. Native `trade` return observed in the paired snapshot reset the index, contrary to the report's blanket statement that row selection persists across switches. The instructions at `0x14031fb7b` and `0x14031fc76` supply candidate writes, not proof of the executed path.

### Existing button code: useful but building-specific

`plugins/ui_panels/ui_panels.cpp:WidgetButtonImplEx` already contains the project's button rendering and input precedent (including `GetMouseSolid`, `Collision`, physical-edge fallback, click deduplication, shared panel fields and clip handling). However it depends on the active `g_frame`, row budget, `g_frame.win`/`live` and window geometry, advances building-window content, and writes shared drawing fields. `AppendWidgetsImpl` explicitly gates providers on a valid building. `src/ui_panels_api.h` describes an in-building widget pass. Therefore the existing method is not a drop-in global-sidebar API: adapt/reuse the established interaction semantics only after separately analyzing frame context, input arbitration, balanced clips, and shared-state restoration. Do not reposition the existing City Hall TAX button.

### Planning implications

Investigate a mod-owned interaction state and separate dynamic button as a candidate, while preserving all eight native controls. Determine a render/content boundary with evidence for avoiding double drawing and clicks, then make close/switch behavior explicit (including clicking another native row item, another sidebar section, or closing the sidebar). Prefer a distinct global section; the Economy & Trade page remains a fallback if needed. First-release content must include government finances and directly adjustable tax policies. A design cannot be declared ready to implement until native content handling, an interaction/render context, hook safety and return behavior have defensible approaches. No synthetic native writes, implementation, deployment, or behavioral test is authorized by this report.
