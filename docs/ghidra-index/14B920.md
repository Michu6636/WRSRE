# FUN_14014B920 — Per-tick Refill Tick (writes vehicle+0x5F0 mirror)

**RVA:** `0x14B920`
**Signature:** `void FUN_14014b920(longlong param_1, ulonglong vehicle)`
**Purpose:** Per-tick vehicle fuel tick. Reads vehicle+0x5F0; does `vehicle+0x5F0 = vehicle+0x5F0 + PowerTime() * vehicle+0xDE0 * prototype+0x428` (a per-tick refill increment), then clamps vehicle+0x5F0 to 0 when it reaches a threshold (`*(int *)(prototype+0x1b0+0x9c)`). Also manages vehicle+0xDE8/+0xDE4 timers and vehicle+0xDDC. Does NOT write the cargo slot (vehicle+0x3B8).
**Callers:** per-tick vehicle update
**Data Refs:** vehicle+0x5F0 (fuel mirror), vehicle+0xDE0, vehicle+0xDE8, vehicle+0xDE4, vehicle+0xDDC, vehicle+0x318, prototype+0x428, prototype+0x1b0+0x9c (full threshold), vehicle+0x970/+0x978 (storage stride 0xE0)
**Artifact:** scratch\out\14014b920_decomp.c
**Notes:** Confirms 0x5F0 is written by a per-tick refill tick (added to), not by burn. 0x5F0 and cargo slot are separate stores statically. Prior corrections named 14B920 "burn adjustment" — disasm shows it is a refill top-up on 0x5F0, not a burn deduction.
**Status:** verified
