# Trade-handler follow-up: independent review

**Scope:** Review of Windows agent [report](../export/almanac-evidence/trade-handler-trace/report.md) from upstream `a6ce145`, compared with the preserved [host](../export/140317db0_full_disasm.asm) and [trade-handler](../export/140373ea0_1403829fd_disasm.asm) instruction exports and earlier [independent review](almanac-export-review.md). No game or mod was run. The source report is preserved unchanged and contains important arithmetic and control-flow mistakes.

## Corrections

- **Entry stride is 80 bytes (`0x50`), not 96.** In the normal row loop, `0x140374179–0x14037418a` uses signed magic multiplication by `0x6666666666666667` and a 5-bit shift to divide a nonnegative span by 80. For example spans 640 and 720 produce counts 8 and 9, respectively. The indexing at `0x1403741f6–0x140374201` independently multiplies the entry index by 80. Separate local entries at `game+0xc7f0` are 16 bytes and must not be conflated with this vector.
- **Appending does not put the new item at position 7.** Before skip conditions, the normal-loop mapping for 8 entries is `[0, 1, 7, 2, 3, 4, 5, 6]`; for 9 it is `[0, 1, 8, 2, 3, 4, 5, 6, 7]`. These are zero-based logical positions. Thus, assuming normal loop execution and no skips, an appended index 8 is visited at the **third** position. The mapping is not a proof of visible coordinates, fit, or clickability. Existing item order remains relative to each other but shifts after the insertion point. If skips are active, visited and visible positions can differ.
- **The two trade handlers are `0x140373ea0` and `0x140361bb0`.** In the host export the trade path compares `game+0x10398` at `0x14031ede6`, calls the first handler at `0x14031edef` when nonzero and the second at `0x14031ee13` when zero. `0x14031edf3` is inside the first call's instruction, not its start. The later `0x140358a20` call at `0x14031ee76` belongs to a separate name-comparison branch; the excerpt does not make it the fallback for all other names or the zero-selector trade handler. A selector snapshot is not proof that the handler executed.
- **The early counter branch is reversed in the report.** At `0x140373fd5`, unsigned greater-or-equal branches to `0x14037403a`, where `game+0x10be8` is set to `-1`. The less-than path executes setup and jumps to `0x1403826f7`. Preconditions, destination cleanup and actual reachability remain context-dependent.
- **Stale-AL issue concerns a hypothetical patch, not the unmodified call.** At `0x140374606` the original helper's return is legitimately tested when the call executes. If someone simply NOPs/skips that call while still falling through to `TEST AL,AL` at `0x140374612`, that test consumes a previous value. The native `selected > 1` branch at `0x1403745f8` jumps directly to `0x14037461b` and bypasses the test. Neither mechanism establishes a safe suppression strategy; the helper has additional side effects.

## Consequences

Reputation's optional append is a valuable lead, but this normal-loop mapping is not the requested clean position **after** the eight native icons. The alternative trade handler, user-visible spacing, clicking, vector ownership, native-content suppression and return remain unresolved. Continue toward dynamically positioning an independent button while reusing working native interaction; an append is only a candidate if those requirements and risks are resolved. A read-only snapshot can report the currently selected pointer, selector, begin/end/capacity and geometry, but cannot prove actual instruction execution, safety, a ninth button's appearance, or clickability.
