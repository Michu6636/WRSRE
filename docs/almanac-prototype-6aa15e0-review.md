# Independent review: Almanac draw-only prototype `6aa15e0`

**Verdict: not ready for a live test.** The submitted code is a disabled-by-default, non-clickable backdrop experiment, not the Almanac or a proven aligned button. No game, plugin, hook, MSVC build or live test was run in this review. An agent-reported Clang cross-compile for a Windows target is documented below. The original four files are preserved byte-for-byte and their Git blobs checked under [`export/almanac-evidence/prototype-agent-6aa15e0/`](../export/almanac-evidence/prototype-agent-6aa15e0/). Agent 2's commit is `6aa15e0f2813e84a81b89dc5e77cd5f37d89edf9`.

## Findings

1. **Selector field read has the wrong width.** The host compares a single byte at `game+0x10398` (`0x14031ede6`, in `export/140317db0_full_disasm.asm`). `ReadGate` reads a 32-bit integer there (`almanac_button.cpp:138`), including unrelated adjacent bytes. A zero selector with nonzero neighboring bytes can pass the nonzero test. The row call site is an additional filter, but does not make the 32-bit value the selector or prove the selected context.
2. **One pass is not established by an X-coordinate sequence.** The tracker uses a global mutable object and a hypothesized origin to group calls. It does not establish invocation/frame boundaries, threading or reentrancy; an unreadable state returns without resetting it (`almanac_button.cpp:217–219`). It checks count every call, but selector, skip flags and row mode only on the final call, and never checks Y consistency (`almanac_button_geometry.h:100–136`). An independent synthetic [probe](../export/almanac-evidence/prototype-agent-6aa15e0/review-probe.cpp) confirms that an eighth input with Y=800 after seven at Y=196, or a skip flag changing before the last input, still returns `DrawNinth`. These inputs demonstrate missing rejection logic, not that either sequence happens in game. Add appropriate pass-boundary, stable-state and failure/reset protections; if a defensible boundary cannot be established, stop rather than draw.
3. **Fault restoration is not safe or guaranteed as described.** `DisarmAfterFault` ignores the return of `PatchIat` and always logs restoration (`almanac_button.cpp:194–200`). It unconditionally writes the saved pointer without checking that the slot still belongs to this detour, so it could replace another plugin's later hook. The helper's check and swap are separate operations, not an atomic ownership protocol. Exception handling also retries a potentially faulting memory restore and catches exceptions from the extra engine Draw; it does not prove game renderer state is intact. Define ownership, conflict, concurrency and failure handling; report actual outcomes instead of claiming success.
4. **The draw mutates native shared UI state.** `DrawNinthTile` writes the shared rectangle globals (`almanac_button.cpp:249–250`) and calls the engine Draw a second time. It saves/restores 20 rectangle bytes, but other graphics state, clipping, effects, reentrancy and concurrent use have not been shown to be unaffected. Its readonly pointer check does not itself establish safe writability. The configuration comment that it changes no native state is therefore incorrect. Nor is a numerical rectangle in handler coordinates proof of actual fit or alignment.
5. **The build guard is weaker than described.** `TsmCheckExeBuild` may accept a matching `addresses.ini` target or `allow_unverified_exe` (see `src/game_addresses.h`), not just the baseline stamp. Two short call-site byte strings and three float values are checked; they do not authenticate the build or verify the whole row, flags and layout. Define and independently check the intended build identity and what each guard actually establishes.
6. **Test coverage and runtime claims.** The original nine host test functions passed with `g++ -std=c++17 -Wall -Wextra -Werror -pedantic`. They test modeled inputs only, not the Windows glue, hook chaining, native shared state, pass ownership, clipping, executable identity, or actual clickable/visible controls. The plugin has not been compiled for Windows. Its reused eighth-tile tint/hover and non-clickable backdrop are known scope limits, not usable final behavior. The proposal to disable taxes and ledger contradicts the representative City Hall baseline agreed after the earlier plan; that setting is not approved.

## Follow-up: revision `2814161`

The [five original revision files](../export/almanac-evidence/prototype-agent-2814161/) are preserved byte-for-byte and their Git blobs verified. Independently built 21 host test functions; all passed. The previous synthetic mixed-Y and changed-gate probes now correctly return `None`. Single-byte selector reading and reset-on-unreadable are present. The review resulted in meaningful improvements, but this revision is **still not ready for a live test**:

1. **Scale/geometry changes are not tracked.** `RowTracker` saves Y and gate but recomputes origin/pitch from the current `RowConstants` on every call. A synthetic [scale-change probe](../export/almanac-evidence/prototype-agent-2814161/review-scale-probe.cpp) feeds seven samples at scale 0.8 and an eighth at 1.0, each matching that call's own X formula; the tracker returns `DrawNinth` at X=642.0. This shows the missing consistency check, not a real observed game sequence. Consistent X/Y and gates still do not establish a frame, invocation or thread boundary.
2. **Native drawing faults are caught contrary to the documentation.** The additional `g_drawOrig` call (`almanac_button.cpp:340`) is inside `__try` and `__except (EXCEPTION_EXECUTE_HANDLER)` handles it (`:330–350`), despite the claim that native Draw faults are not caught. The handler also calls `memcpy` while handling a potential rect-write or restore fault, risking a second exception. Define actual fault containment and correct the documentation; do not continue after potentially corrupting game/render state.
3. **Hook ownership remains check-then-write.** `RestoreOriginal` checks `*g_slot`, then calls `PatchIat`, whose implementation unconditionally assigns the slot; another writer can intervene (`almanac_button.cpp:261–275`, `src/tesmioloader.cpp:195–208`). Startup has a similar race. Read-back after a write cannot undo an overwritten hook; claims it 'never overwrites' a foreign value are too strong. If coordination or safe ownership cannot be guaranteed, stop rather than patch.
4. **The start lifecycle is described incorrectly.** `StartPlugins` in `src/tesmioloader.cpp` logs a nonzero Start result and does not unload the plugin. Unloading on decline is an `Init` behavior. In the post-swap mismatch path (`almanac_button.cpp:440–447`), another hook could have captured the detour; clearing `g_drawOrig` could then make that detour swallow calls even though it remains loaded. The path's 'import unchanged' claim is also not established when a different value is observed.
5. **Build/test scope.** A PE timestamp is a header field, not a whole-file check, and `TsmCheckExeBuild` can accept an `addresses.ini` build override as well as `allow_unverified_exe`. The code checks two byte sequences, not three. It does not authenticate row semantics. The README again proposes disabling taxes and ledger, contrary to the representative configuration previously agreed; keep settings representative and avoid tax edits, saves or time advancement in the first alignment experiment. Windows compilation and live behavior remain unverified.

## Follow-up: revision `a9bb5a2`

All five revision files are preserved under [prototype-agent-a9bb5a2](../export/almanac-evidence/prototype-agent-a9bb5a2/) with Git blobs verified against `a9bb5a289338b251135409c6e4e2ec01c4df31b8`. Independently ran all 24 host test functions and three earlier synthetic probes; all tests pass and the probes now reject the mixed Y, skip and scale cases. The use of compare-exchange improves slot ownership, lifecycle wording is corrected, native draw calls are no longer inside the plugin's `__try`, and the recommendation to disable taxes and ledger is gone. **A live test is still not recommended:**

1. `WriteNinthSlot` (`almanac_button.cpp:358–370`) makes two separate writes and assumes that a fault during either means neither changed, because they share a page. This is not guaranteed: the first store may succeed and the second may fault, for example if protection changes between them. The error path (`:386–389`) restores the import but leaves the saved rect unrestored, and returns to the game. The same-page premise is insufficient to claim a transactional write. Define a safe partial-failure/rollback or stop policy, including failure during restore; do not claim the rectangle is unchanged.
2. In `TsmPluginStart` (`:475–488`) the engine pointer is checked against `*slot`, but the code rereads `*slot` into `original` before compare-exchange. A foreign writer that installs another pointer between those two reads can be adopted as the expected original and successfully replaced even though the design says it refuses an already-hooked slot. Compare against the exact validated expected pointer and preserve forwarding correctness; account for subsequent chaining and concurrent page-protection changes. Compare-exchange does reduce the check/write race but is not a general coexistence guarantee.
3. `CompareSwapSlot` (`:276–285`) reports `protectOk` as true after making the page writable even if restoring its original protection fails; startup can then arm after only logging a warning. Treat pointer swap success and protection restoration as distinct outcomes and specify the safe failure response; an unexpected writable IAT page must not be silently treated as an ordinary success.
4. A consistent geometry sequence remains a candidate, not proof of a native invocation, render-thread exclusivity, a real visible edge, clipping, or safe extra draw. Existing tests cover modeled tracker logic only; the Windows glue, SEH, ABI, slot protection and concurrent hooks are not tested. `TsmCheckExeBuild` also accepts compatible `addresses.ini` overrides or an explicit forced allowance; documentation must not promise only a baseline-stamp match. A normal game test or injected fault remains unauthorized.

## Follow-up: revision `ced5534`

The [five original files](../export/almanac-evidence/prototype-agent-ced5534/) are preserved byte-for-byte and verified against `ced5534f7e9e5a373c267b84e9de719d2afb877e`. All 24 host test functions pass. The revision uses the exact validated export pointer for the compare-exchange, separates protection results, describes the build-guard limitations and replaces two position stores with an aligned pair operation. Windows compilation, the generated instructions and runtime behavior remain unverified.

**Recommendation: do not approve a live game test as written.** The proposed choice between accepting a dirty session and proving a restoration can never fail is too narrow: a specific containment/stop plan is possible, but it must be reviewed and separately approved. Findings:

1. **Dirty rectangle path continues game execution.** If the restore store fails (`almanac_button.cpp:464–469`), the plugin logs, attempts to restore the import and returns to the native caller. There is no automatic stop, and the current pair is not necessarily the ninth pair: the extra engine Draw may have modified it. Its effect on later rendering or input is unknown. Logging alone does not establish that the process stops before subsequent game work or save activity. In addition, a native Draw fault exits before the pair restoration; propagation does not prove that an outer handler cannot resume with changed state. Distinguish these cases and specify a safe containment/stop policy for a disposable session without claiming all failures are impossible.
2. **Undo can restore the wrong page protection.** `CompareSwapSlot` records its own starting protection (`:315–326`). If the first restoration fails after changing an originally read-only page to read/write, startup immediately calls `CompareSwapSlot` again for the undo (`:585–592`). The second attempt can record read/write as its `oldProt` and successfully restore that writable value, then log 'page protection restored', even though the original read-only protection was not restored. Preserve and correctly report the original protection across undo; account for concurrent changes and failure without asserting success.
3. **One 64-bit C++ store is not yet independently established at machine-code level.** The x64 alignment is checked, but there has been no MSVC build or disassembly of the resulting store; the exception/atomicity claim is not tested here. The extra Draw can mutate shared state outside the X/Y pair and the tracker does not prove invocation/thread boundaries. The prototype remains draw-only, noninteractive and experimentally scoped.

## Follow-up: revision `b5c207d`

The [five original files](../export/almanac-evidence/prototype-agent-b5c207d/) are preserved byte-for-byte and verified against `b5c207dd865e7c9cc124d528323182dc17687e5a`. All 24 Linux geometry test functions pass. The code now retains the initial import page protection across an undo and stops arming on failure. It proposes a fail-stop policy for rect faults and catches the ninth Draw fault before stopping the process; this is a deliberate behavior change, not yet approved for a game test.

**Supplementary compile report (agent-reported; not independently reproduced here):** the agent created a scratch archive of the exact commit and used Zig's Clang 22 to compile `almanac_button.cpp` for `x86_64-windows-gnu` with `-std=c++17 -O2 -fms-extensions -Wall -Wextra`. It reports an object file and zero errors, with eight `-Wunused-function` warnings in the shared `src/tesmio_plugin.h`; an existing `ui_overlay` comparison reportedly showed the same warning class. This is useful evidence that Clang accepts and generates code for this source under its Windows GNU target, but it is **not MSVC**, not the repository's `build.bat`, and not a link. A separate Clang `x86_64-windows-msvc` attempt stopped at missing `malloc.h`, so that attempt is inconclusive. Compiler logs and the object were not supplied in this workspace, and I have not reproduced either attempt. No Windows/MSVC compile result is available.

This remains **not approved or ready for a live game test**. Specific caveats:

- `FailStop` calls `Logf` twice before `TerminateProcess`. The loader logger acquires a critical section and invokes `WriteFile` (`src/tesmioloader.cpp:82–108`); it does not explicitly flush on ordinary log writes or check the result. A logger lock, invalid handle, I/O failure or hang could prevent the marker and/or delay termination. A log-watching watchdog alone cannot detect a failure before the marker is written; an independent timeout/liveness strategy and test isolation must be reviewed before any live test. A crash-handler flush on a different path is not evidence that these log lines are durable.
- The extra Draw is now inside SEH; it restores the rect after a caught fault and requests process termination. This differs from propagating the ninth draw fault and can lose unsaved work or interrupt saves. It is acceptable only as an explicitly approved experimental policy in a genuinely isolated disposable setup, not silently as a production behavior. Whether the stop procedure actually works is untested.
- Retaining the initial page protection corrects the specific undo issue previously identified; compare-exchange and protection changes still lack a process-wide ownership protocol, and concurrent hooks/page-protection changes, exception handling and MSVC-generated 64-bit instructions are unverified. The proposed VM and unwritten log watchdog are agent proposals, not a demonstrated universal requirement or an approved test setup. Any final isolation and containment procedure needs a separate review, including copied save paths and cloud sync.
- `build.bat almanac_button` has **not** run. It requires MSVC and runs `clean.bat`, which deletes `*.obj`, `*.exp`, `*.lib`, `*.ilk` and `*.pdb` recursively from its working tree; an eventual build should use an isolated scratch checkout. Do not ask the user to run Visual Studio. If an actual Windows/MSVC agent is available, the bounded compile/link check may still be requested separately; it must not install/load the DLL or launch the game.
- The plugin only draws a backdrop and has no Almanac input. Its assumed row pass, scaling, clipping, all native clicks and engine shared state remain unproven.
