## Important specification corrections

1. **Property unit provenance is not recoverable from startup alone.** `LoadTaxes` may replace `g_propertyTaxFlat` with a value from a tax side file that contains no currency field, and a setter can later replace it. Recording the active currency at Start as the stored value's proven unit can falsely label legacy data. The existing API describes setter input as active-currency units, but historical saved values and currency changes require explicit unknown provenance, write protection when units are uncertain, and a future compatibility/migration design. The spec's §3.2 asserts config defaults after a rejected load; actual values remain whatever was already in memory, potentially including prior loaded or adjusted policy. It must not assert the exact fallback without tracing lifecycle.
2. **Finance validity needs observable facts, not invented flags.** Ledger currently discards flow currency and does not track startup completeness, observer loss, all unrelated native treasury moves, or every save/load provenance. A snapshot that leaves flow accumulation unchanged cannot detect a deliberately injected non-active-currency flow as PoC-1 requires. Preserve unknown unless instrumentation actually tracks from a known baseline; distinguish coverage of labelled events from full treasury movements and a mathematically computed divergence from reconciliation confidence. Recording a tick does not by itself make separately read balances and asynchronous flow callbacks an atomic snapshot.
3. **The PoC stop conditions conflict with expected behavior.** User clicks on a native tile legitimately change native selection; the stop condition must distinguish intended native interaction/original game stores from unintended mod-origin changes. A data PoC must change source/plugin files and produce build outputs, so `git status` cannot categorically forbid every repo change outside `docs/` and `export/`. Baseline ordering can vary by game mode; stop on unintended regression relative to measured baseline, rather than declaring any movement automatically a defect. Explicitly record all expected writes, test copies and restored artifacts.
4. **Service availability and UI conflict.** §2.4 closes on a service becoming unavailable but §2.4/§5.1 also open unavailable content. Specify a coherent policy that preserves visibility of unaffected finance or tax sections. Failure to resolve a tax provider should say 'service unavailable', not assert that no tax can possibly be charged by anything. Detection and close behavior for Esc, section changes and repeated clicks remain unproven, not guaranteed by an index alone.
5. **Don't hard-code unproved UI mechanics.** A1 assumes input-before-native even while §2.3 says ordering is open; the Collision/GetMouseSolid pair is an implementation lead, not a proven global-row hit test. A separate global panel may use a draw/hit-test host or other integration; `ui_overlay` offers HUD drawing but not a proven sidebar host. A missing global host does not establish that the Economy & Trade fallback is immediately viable. Preserve dynamic layout and all eight native icons plus the Almanac in one row.
6. **Tax validation and API compatibility.** Rejecting nonfinite values only in the Almanac leaves the existing service boundary exposed to other callers; this deserves an explicit later decision and tests. An append-only v3 with compatible v1/v2 views and accurate sizes is one possible design, not a proof that legacy binaries automatically access new pointers. Do not force a City Hall slider ceiling as an unexplained policy limit or truncate an existing valid value; define how bounds and current values are presented. A lock-protected snapshot is coherent within its contract; a generation number alone cannot prove cross-service or persistence consistency.
7. **UI actions must handle suspension and save/load honestly.** The property label depends on the *active* basis, not the shipped default; expose the setting or mark it unavailable. Test loaded, suspended, City Hall-modified and nonfinite values. A return after user interaction must preserve native behavior; calling the desired panel 'global' does not itself establish content replacement, layering, close or return safety.
8. **Other evidence corrections remain in** [agent comparison](almanac-agent-comparison-review.md) **and** [design comparison](almanac-design-comparison-review.md): Reputation-specific H1 is not an Almanac failure, index 2's vector identity differs from third visual position, candidate growth is not the same as a proven safe append, and the alternate loop's omission is path-specific. Agent-original superseded docs should remain unchanged, with any corrections in a separate visible review.
